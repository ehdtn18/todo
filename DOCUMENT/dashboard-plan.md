# 대시보드 기획서 (구현 전 · 컨펌 대기)

> 목적: 앱을 켜자마자 **한눈에 현황 파악** — 진행 상황, 임박한 마감, 연차, 이번 주 일정.
> 추가 DB 없이 기존 `tasks`/`leaves` 데이터로 모두 계산.

## 1. 진입 위치 (택1 — 컨펌 필요)
- **(A) 뷰 탭에 추가** — 상단 `리스트 / 칸반 / 달력` 옆에 **`대시보드`** 탭 추가. (추천)
- (B) 홈 최상단 — 작성 폼 위에 요약 카드 띄우기.
- (C) 별도 모달 — 헤더 아이콘으로 열기.

## 2. 레이아웃
- 토스 스타일 **카드 그리드**. PC 2~3열, 태블릿 2열, 모바일 1열(반응형).
- 각 카드 우상단에 "전체 보기" → 해당 뷰로 이동.

## 3. 위젯 구성

### ① 오늘 요약 (히어로 카드)
- 진행률 도넛(완료/전체 %) + 오늘 마감 N건 / 지난 마감 N건.
- "오늘 할 일" N개 · 남은 일 N개.

### ② 마감 임박 Top 5
- D-day 가까운 순 5개. 각 항목: 제목 · 기간 · D-day 배지. 클릭 → 해당 할 일로 이동·강조.

### ③ 상태 분포 (칸반 요약)
- 시작전 / 진행중 / 완료 / Drop 개수 + 가로 막대 비율.

### ④ 우선순위 분포
- 높음 / 중간 / 낮음 개수 막대.

### ⑤ 이번 주 일정 미니뷰
- 이번 주(일~토) 7칸에 일정 막대 요약. 클릭 → 달력 주간 보기로.

### ⑥ 연차 현황
- 올해 사용 / 잔여를 게이지(또는 도넛)로. 예: "8일 4시간 남음 (15.5일 중)".
- 다가오는 예정 연차 1~2건.

### ⑦ 중간컨펌 진행
- 컨펌 단계가 있는 할 일들의 진행률(예: "프로젝트 A — 2/3 컨펌 완료").

### ⑧ 최근 활동
- 최근 추가/수정된 할 일 3~5개(수정 이력 기준).

## 4. 상호작용
- 모든 카드/항목 클릭 → 해당 뷰 또는 할 일로 이동(+하이라이트, 알림 클릭과 동일 동작 재사용).
- 다크모드/반응형/마이크로 인터랙션 기존 디자인 시스템 그대로.

## 5. 구현 메모(참고)
- 별도 API/테이블 불필요 — 클라이언트에서 `tasks`/`leaves` 집계.
- 진행률 링은 예전에 제거한 게이지를 이 안에서 재사용.
- `renderDashboard()` 한 함수에서 카드 HTML 생성(기존 render 패턴 동일).

## 6. 컨펌 필요 항목
- 진입 위치 A/B/C?
- 위젯 8개 중 1차로 넣을 우선순위(예: ①②③⑥ 먼저)?
- 차트는 순수 CSS 막대/도넛으로(라이브러리 없이) 진행해도 되는지?
